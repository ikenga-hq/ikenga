Close the viewer-mount widening hole, in browser sessions and in the desktop app. The preview root is computed from the page's own `../` references, so a hostile HTML file could widen it to the whole home and `fetch()` credentials out of it. `viewer_serve` now takes the page being previewed (`filePath`) and refuses, with an error rather than a silent clamp, any root above that page's project root from the host's own project registry (or, for a page in no project, above its own directory). When that bound is the home directory, an ancestor of it, or `/` (a page straight in `~`, or in a project rooted at the home), the mount is single-file: only the previewed page is served and every other path under it is a 404, so the preview still works but cannot read anything else. Every viewer request also refuses credential paths with a plain 404, in any mount: any path component named `.ssh`, `.claude`, `.aws`, `.gnupg`, `.config`, `.netrc`, `.git-credentials`, `.docker`, `.kube`, `.env` or `.env.*`, and `id_rsa`/`id_ed25519`-style private keys. The desktop viewer server now resolves files to a canonical path inside the mount before serving them, so a symlink that leaves the mount root is a 404 there too. The preview pane clamps its request to the project root, so pages that reach shared assets inside the project keep working. Both viewer CSPs (daemon `/__viewer` and the desktop viewer server) no longer allow `https:` for `img-src` and `media-src`, which closes the remaining channel for sending what a page read to an outside host.
